## Executive Summary

The branch adds automatic checkout detection, persistent repository-view metadata, and canonical-plus-branch search composition across ingest, search, federation, MCP, and CLI paths. Consensus identifies three unresolved correctness failures: branch deletions never produce durable tombstones, overlay overrides are derived from a bounded semantic-candidate set, and federated requests discard the requested view. These failures can return stale canonical content or inconsistent cross-peer results, so the branch requires revision.

## Blocking Issues

- Branch deletion tombstones are never created (ingest/src/lib.rs): compute_deleted_branch_paths is unused, path_state is always written as present, and branch cleanup removes branch rows without creating deleted tombstones. Consequently, files deleted on a branch cannot durably shadow canonical content.
- Branch overrides are discovered only within bounded search results (search/src/lib.rs): Search retrieves a limited semantic candidate set before deriving overridden paths. If a branch replacement or deletion is outside that window, the corresponding canonical row can remain in the results despite being overridden.
- Federated search drops the requested view (mempalace-mcp/src/federation.rs): The federation router constructs remote DrawerSearchRequest values with view: None, so branch-scoped searches combine correctly scoped local results with unscoped canonical remote results.

## Non-Blocking Issues

- View composition performs an unbounded drawer scan: Tombstone discovery calls list_drawers without a limit or dedicated filtered lookup, which can scan every drawer in a view and degrade substantially for large repositories.
- Conflicting --branch and --full flags are silently resolved: Passing both flags causes --full to override --branch without an error or explicit user-facing explanation.
- Direct ingest callers can mishandle view canonical: ProjectIngestRequest with branch=true and view="canonical" is not normalized in the ingest layer and may create a branch named canonical; only the CLI currently handles this combination.
- Automatic branch detection changes routing without warning: Auto-detected branch mines force local storage even when routing configuration would otherwise select remote storage. This is documented behavior for branch deltas but merits a warning or clearer compatibility documentation.

## Missing Tests

- End-to-end branch deletion tests proving tombstones are created, persist across re-mines, and shadow canonical results.
- Search tests where a branch replacement or deletion falls outside the initial semantic candidate window.
- Storage-backed overlay tests covering additions, updates, deletions, and unrelated repositories.
- Federated search tests proving the requested view is forwarded to remote peers.
- Real Git checkout-detection tests for canonical branches, feature branches, detached HEAD, symbolic origin/HEAD, and linked worktrees.
- Lance migration tests that populate and round-trip all new view-metadata columns.
- Direct API tests for view="canonical" when branch=true.
- Tests covering branch tombstone handling when skip_unchanged is active.

## Disputed Issues

- Whether ingest_mode can be NULL in reachable legacy data; reviewers concluded the column is historically non-null, so the SQL NULL-filter concern is not consensus.
- Whether schema migration is missing; reviewers confirmed ensure_schema already adds the new columns.
- Whether canonical stable-key cleanup leaves stale deleted files; the concern is plausible but existing per-file cleanup may cover it, so it is not consensus.

## Outstanding Concerns

- Automatic checkout detection changes the default behavior of mining on non-canonical branches and may surprise existing scripts or users despite --full being available.
- The current implementation does not demonstrate complete full-search semantics across every CLI and search interface.

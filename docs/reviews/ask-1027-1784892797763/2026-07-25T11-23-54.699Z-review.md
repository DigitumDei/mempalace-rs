```text
Blocking Issues

1. Deletion tombstones survive after a branch deletion is reverted. `compute_deleted_branch_paths` stops returning the restored path, but branch cleanup explicitly preserves records whose hash is `hash_text("removed")` (`crates/mempalace-ingest/src/lib.rs:847-852`). The tombstone drawer therefore remains and continues hiding the canonical file indefinitely. Cleanup must remove tombstones no longer present in the current deleted-path set.

2. The stated full-repository search view is not implemented. Search supports only canonical (`None`/`"canonical"`) or one named branch overlay. There is no CLI, direct API, MCP, federation, or storage-filter representation for searching the entire repository across views.

Non-Blocking Issues

1. Conflicting CLI options remain incompletely handled. `--branch` conflicts with `--full`, but `--full --view feature-x` and `--branch --view canonical` are accepted and silently resolved by precedence. These combinations express contradictory modes and should be rejected or explicitly tested and documented.

2. Legacy `hall = "view:<name>"` rows are selected by storage filtering, but overlay discovery discards every row lacking `view_metadata` (`crates/mempalace-search/src/lib.rs:252-256`). Such branch rows can appear alongside canonical content without shadowing it, contrary to the documented legacy compatibility.

3. Every named-view search performs an unlimited `list_drawers` scan across all wings and rooms to discover overridden paths. This makes search cost proportional to total canonical-plus-view storage, despite most canonical rows being discarded during set construction.

Missing Tests

1. Delete a canonical file on a branch, mine the tombstone, restore the file to canonical contents, re-mine, and verify canonical content becomes visible in the branch view.

2. Real Lance-backed overlay tests covering canonical replacement, tombstone suppression, wing/room filters, and legacy hall-only branch rows.

3. Actual Git repositories testing canonical branch detection, feature branches, linked worktrees, detached HEAD, and missing/stale `origin/HEAD`.

4. CLI parsing tests for every `--branch`, `--full`, and `--view` combination.

5. End-to-end CLI, MCP, server, and federated tests exercising both canonical and branch results—not merely request forwarding.

6. A full-repository search test once that required mode is implemented.

Strong Concerns

The new tombstone regression test verifies only that an unchanged deletion remains durable. That validates persistence but misses the equally important inverse lifecycle: tombstones must disappear when the deletion is reverted.

The prior federation, top-K overlay, direct `"canonical"` normalization, and initial tombstone-writing defects appear fixed in the current branch.

Confidence

High. The tombstone lifecycle failure follows directly from the cleanup condition and is not dependent on vector ranking or storage behavior. The missing full-repository mode is evident across the exposed search contracts. No local build was required for these findings.
```

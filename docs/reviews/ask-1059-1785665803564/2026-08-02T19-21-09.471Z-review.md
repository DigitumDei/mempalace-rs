## Executive Summary

The branch updates the whoami contract to expose the composed principal as identity, aligns related tests and documentation, uses bodyless delegated GET requests, and expands admin write-path coverage. Reviewers found no blocking runtime defect and agreed the implementation is coherent, with remaining concerns limited to audit-event test coverage, duplicate delegation-header handling, and clearer documentation of new info response fields. The branch is therefore ready for a PR.

- crates/mempalace-cli/src/main.rs

- docs/CLI-Surface.md

- docs/Operator-Standard.md

## Blocking Issues

- None

## Non-Blocking Issues

- Repeated delegation headers are silently accepted (mempalace-server/src/lib.rs): The implementation reads only one X-MemPalace-On-Behalf-Of value, leaving duplicate-header behavior ambiguous at a proxy trust boundary; rejecting duplicates would make the identity contract clearer.
- New /v1/info identity fields need clearer federation documentation (docs/Federation.md): The info response now exposes authenticated_token, authenticated_level, on_behalf_of, and composed_identity, but their wire semantics and relationship to whoami's identity field are not clearly described in Federation.md.

## Missing Tests

- Verify delegated KG add and KG invalidate requests record the composed principal in their change-event actors.
- Verify a read-level token with a valid delegation header is still rejected with 403 on write routes.
- Add coverage for repeated delegation headers and define the expected behavior.

## Disputed Issues

- Whether the info response's identity fields are insufficiently documented, since they have struct-level documentation but lack detailed endpoint documentation.
- Whether defensive refactors such as direct AccessLevel serialization, fail-safe require_write handling, and duplicate admin-plus-delegation tests provide enough value to warrant changes.

## Outstanding Concerns

- Token names are not restricted from containing ':', which can make composed identities ambiguous, although token configuration is trusted.
- Rust compilation and tests were unavailable in the review environment and should be validated by CI.

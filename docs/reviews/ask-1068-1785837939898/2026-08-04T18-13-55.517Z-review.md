## Executive Summary

The branch substantially rewrites ignore handling and Git-backed source discovery to address issues 95 and 96. Reviewers reached consensus on two Git-index discovery defects: tracked symlinks can escape the repository boundary, and intermediate ancestor .mempalaceignore files are skipped. Because the symlink issue can ingest files outside the repository and the exclusion gap can bypass explicit user exclusions, the branch requires revision before PR submission.

## Changed Files

- crates/mempalace-cli/src/main.rs
- crates/mempalace-ingest/src/lib.rs
- docs/CLI-Surface.md
- docs/Mined-Storage.md

## Blocking Issues

- Tracked symlinks can escape the repository boundary (crates/mempalace-ingest/src/lib.rs): Git-index discovery uses fs::metadata, which follows symlinks; a tracked symlink targeting a file outside the repository can therefore be read and mined, violating the safe-root boundary.
- Intermediate ancestor .mempalaceignore files are not loaded (crates/mempalace-ingest/src/lib.rs): For a tracked path such as a/b/file.rs, discovery loads ignore files from the root and immediate parent a/b but skips a/.mempalaceignore, allowing explicitly excluded tracked files to be mined.

## Non-Blocking Issues

- SSH key denylist produces false positives (crates/mempalace-ingest/src/lib.rs): Prefix matching classifies public keys such as id_ed25519.pub and unrelated names such as id_dsa_notes.md as private keys, reducing discovery coverage.
- Conversation discovery behavior expanded implicitly (crates/mempalace-ingest/src/lib.rs): Conversation discovery now inherits nested ignore files, repository and global excludes, and Git subprocess execution; this behavioral change should be documented or deliberately scoped.
- Unreadable global excludes files abort discovery (crates/mempalace-ingest/src/lib.rs): The implementation treats missing excludes files as empty but propagates other I/O errors, such as permission failures, despite comments suggesting unreadable files are ignored.
- Ignore rules are repeatedly resorted (crates/mempalace-ingest/src/lib.rs): Sorting the complete rule set after every directory load can create avoidable O(D * N log N) overhead for repositories with many nested ignore files.

## Missing Tests

- Verify that a tracked symlink pointing outside the discovery root is neither discovered nor read.
- Verify that a tracked a/b/file.rs honors a/.mempalaceignore.
- Test nested ignore precedence across multiple ancestor levels.
- Define and test SSH public-key and prefix-collision denylist behavior.

## Disputed Issues

- The claim that \a must match a literal backslash-prefixed filename is unsupported; git behavior matches the implementation.
- The .env suffix classification is intentional and documented, so treating prod.env as a secret is not a defect.
- Un-negatable built-in skip directories are documented behavior rather than a meaningful regression.
- The proposed trailing-whitespace expectation for double backslashes is incorrect.
- The non-UTF-8 path concern is overstated on Unix, where arbitrary path bytes are preserved.

## Outstanding Concerns

- The conversation-discovery expansion may affect existing mining workflows and should be explicitly documented or covered by tests.
- The global excludes error-handling behavior should be reconciled with its comments and Git semantics.

# Blocking Issues

None. The code compiles cleanly, error handling is correct, and the core design is sound.

# Non-Blocking Issues

1. **`glob_component_match` treats `\` as a glob escape for all characters, diverging from git's `\` semantics.** In git, `\` only escapes `#`, `!`, and `\` itself at the start of a pattern. The implementation intentionally treats `\*` as matching literal `*` (not every file), which is a pragmatic deviation documented in `parse_ignore_pattern_escapes_only_literal_hash_and_bang`. However, a pattern like `\a` in a `.gitignore` would match the literal filename `\a` in git but matches `a` in this implementation. The `\*` behavior is the important case and is handled correctly; the `\a` case is vanishingly rare in real `.gitignore` files.

2. **Performance regression from `sort_rules()` called after every `load_directory`.** Each `load_directory` call sorts the entire `rules` vec via `sort_by`, giving O(D * N log N) where D is the number of directories with ignore files and N is the total rule count. For large projects with many nested `.gitignore` files this could be noticeable. The rules could be sorted incrementally (binary insertion) or only once at the end of the walk.

3. **`discover_conversation_files` now gets the full ignore-handling rewrite (nested files, `$GIT_DIR/info/exclude`, global excludes) without being mentioned in the intent.** The old conversation discovery only loaded root-level `.gitignore`/`.mempalaceignore`. The new behavior is arguably correct, but it's a silent behavioral change that could affect existing conversation mining workflows, and it now spawns `git` subprocesses during conversation discovery.

4. **`secret_path_kind` uses `starts_with(".env")` OR `ends_with(".env")` for `DotEnv` detection.** The `ends_with` check is overly broad: a file named `production.config.env` would be withheld as a secret. Real secret files use `.env` as a prefix (`.env.local`, `.env.production`) or are the exact file `.env`, not as a suffix. The test validates `prod.env` as a secret, but this pattern is unusual for actual secret files.

5. **`global_excludes_path` always returns a path, and `load_pattern_file` propagates I/O errors other than `NotFound`.** If the global excludes file (`~/.config/git/ignore` or `core.excludesFile`) exists but is unreadable (permission error), the entire discovery fails. The comment says "treating unreadable/missing exclude files as empty" but the code only handles missing (NotFound), not permission-denied or other errors. This could be a regression for users with broken or inaccessible global excludes files.

6. **The `matches_skip_dir` function now short-circuits before rule evaluation, making built-in skip directories absolute and un-negatable.** In the old code, skip dirs were rules in the `IgnoreRule` vec, so a `!node_modules` rule could theoretically re-include them (though negation wasn't supported in the old parser). The new code checks `matches_skip_dir` before any rules, making skip dirs truly absolute. In practice nobody would negate `node_modules`, but the behavior is now different from the old code's theoretical model.

# Missing Tests

1. **No test for `GitIndexUnavailable` error path in CLI.** The new `IngestError::GitIndexUnavailable` variant is not tested in the CLI's error handling. The `ingest_error` function uses `to_string()` which would format it via the `Display` derive, but there's no test confirming the error message renders usefully for the user.

2. **No test for `detect_rooms` with all files at root level.** When all eligible sources are at the root (e.g., only `README.md` at the project root), `discovered` is empty and rooms fall back to "general" only. The `file_count` would be non-zero while `source` is "fallback", producing something like `(5 files found, rooms detected from fallback)`. This edge case is untested.

3. **No test for `strip_unescaped_trailing_whitespace` with `\\ ` (backslash-backslash-space).** Git's behavior for `\\ ` is: the first `\` escapes the second `\` (literal backslash), and the space is quoted by the preceding backslash so it's not stripped. The pattern should match a file literally named `\ ` (backslash, space). The current implementation may not handle this correctly due to the interaction between `strip_unescaped_trailing_whitespace` and `glob_component_match`'s backslash handling.

4. **No test for `discover_project_sources` failure when `git ls-files` succeeds but lists non-UTF-8 paths.** The `path_from_git_bytes` fallback silently skips non-UTF-8 paths, incrementing `skipped`. This is untested.

5. **No test confirming that `conversation` mining does NOT apply the secret denylist.** The `discover_conversation_files` accept function only returns `Eligibility::Eligible` or `Eligibility::Excluded`, never `Eligibility::Secret`. This is intentional (issue #95 is scoped to project mining), but there's no test documenting this boundary.

# Strong Concerns

1. **The `discover_files` function now applies `$GIT_DIR/info/exclude` and the global excludes file to ALL callers, including `discover_conversation_files`.** The old conversation discovery was a simple extension-based filter with root-level ignore files. The new code adds nested ignore files, repository-level excludes, and global excludes to conversation discovery. While the behavior is arguably more correct, it's a significant behavioral change outside the stated scope of issues #95/#96, and it now spawns `git` subprocesses during conversation discovery which could affect performance and reliability.

2. **The `detect_rooms` function now requires `fs::metadata` to succeed for every tracked index entry in Git-backed roots.** If a tracked file was committed but the working tree is on a network filesystem that temporarily fails `fs::metadata`, the file is skipped (counted as `skipped` in `discover_git_index_sources`). The old code would have still detected a room from the directory's existence. This is a minor robustness trade-off.

# Confidence

High. The implementation is thorough, well-tested, and correctly addresses both issues #95 and #96. The core design decisions — tracked-index source set for Git repos, git-compatible ignore semantics, and the path-based secret denylist — are sound. The rewrite of the ignore matcher from a flat list of simplified rules to a proper scoped, tiered, last-match-wins system with git-compatible glob matching is a significant improvement. The tests cover the key scenarios well, including regression tests for the trailing-`/**` bug and the `\*` "ignore everything" bug. The concerns above are edge cases and behavioral changes that are unlikely to affect real-world usage, with the exception of the conversation discovery change (concern #1) which could silently alter existing conversation mining behavior.

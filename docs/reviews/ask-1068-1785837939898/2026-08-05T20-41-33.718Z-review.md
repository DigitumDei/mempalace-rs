## Executive Summary

The branch hardens Git-aware source discovery, ignore handling, symlink rejection, branch mining, and stable-key cleanup. Reviewers consistently found that subdirectory branch mines drop eligible untracked files and that incomplete discovery can delete valid durable rows during canonical reconciliation, so the branch is not ready. Remote reconciliation remains scope-dependent and is called out separately as an outstanding concern.

- docs/CLI-Surface.md

## Blocking Issues

- Subdirectory branch mines drop untracked files (crates/mempalace-ingest/src/lib.rs): git diff emits repository-relative paths while git ls-files --others from a repository subdirectory emits project-relative paths; treating both as repository-relative causes eligible untracked files to be filtered out.
- Stable reconciliation can delete valid rows after incomplete discovery (crates/mempalace-ingest/src/lib.rs): The canonical sweep treats every undiscovered path as stale, but tracked files absent from a sparse or partial working tree are skipped during discovery. A re-mine can therefore delete valid stable and legacy rows, including rows shared across checkouts, without authoritative evidence that the files were removed.

## Non-Blocking Issues

- Untracked file symlinks can be followed: Filesystem discovery rejects tracked symlinks in Git-index mode but can open eligible untracked file symlinks through their targets during non-Git and branch-untracked walks, potentially ingesting content outside the project root.
- Nested ignore-file read failures abort discovery: Non-UTF-8 or unreadable nested .gitignore or .mempalaceignore files propagate errors and abort the mine, unlike the tolerant handling of repository-level excludes.
- .env denylist boundary is inconsistent: The starts_with(".env") predicate withholds names such as .envrc and .environment, while other documentation and descriptions imply the narrower .env/.env.* family.

## Missing Tests

- Branch mining from a repository subdirectory containing an eligible untracked file.
- Canonical re-mining from a sparse or partial checkout with tracked files absent from the working tree, verifying existing rows are preserved.
- An authoritative empty-project re-mine versus an incomplete zero-source discovery case.
- Untracked file symlinks in non-Git canonical and branch-untracked discovery.
- Nested non-UTF-8 or unreadable ignore files.
- .envrc, .environment, and .envoy.rs denylist boundary cases.
- Remote or combined canonical re-mining after a previously ingested source becomes ineligible.

## Disputed Issues

- Whether federated or combined canonical ingestion is required to purge stale remote rows, and therefore whether the missing remote reconciliation protocol is blocking.

## Outstanding Concerns

- Federated canonical ingestion only performs additive per-file updates; remote-only and dual-write re-mines cannot reconcile stale rows because the batch protocol has no complete snapshot or deletion semantics. If canonical cleanup is intended to cover remote routes, this must be addressed or explicitly scoped out in the documentation.

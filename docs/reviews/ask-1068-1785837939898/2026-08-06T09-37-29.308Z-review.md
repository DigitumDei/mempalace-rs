## Executive Summary

The branch fixes subdirectory branch discovery, incomplete tracked-worktree reconciliation, symlink rejection, and `.env` boundary matching, with the core local behavior broadly validated by the reviewers. However, canonical cleanup is implemented only for local ingestion: remote-only and `write: both` mines upload current files without deleting stale remote rows, while the documentation implies reconciliation is universal. The branch therefore requires revision before PR.

## Changed Files

- crates/mempalace-cli/src/main.rs
- crates/mempalace-ingest/src/lib.rs
- docs/CLI-Surface.md
- docs/Mined-Storage.md

## Blocking Issues

- Remote canonical mining does not reconcile stale rows (crates/mempalace-ingest/src/lib.rs): Remote batch ingestion is additive and has no snapshot, deletion, or reconciliation semantics. Remote-only mines retain previously stored files that become excluded or secret-shaped, and `write: both` can leave the remote replica stale even after local cleanup. The documentation must either scope canonical cleanup explicitly to local ingestion or the protocol must support safe remote reconciliation across batches.

## Non-Blocking Issues

- Stale removed_sources documentation: The public comment says this count is always zero for non-branch runs, but canonical reconciliation now increments it.
- Incomplete DotEnv API documentation (crates/mempalace-ingest/src/lib.rs): The implementation matches `.env`, `.env.*`, and names ending in `.env`, while the variant documentation mentions only the first two forms.
- Nested ignore files require UTF-8 and can abort discovery (crates/mempalace-ingest/src/lib.rs): Nested `.gitignore` and `.mempalaceignore` files are read as UTF-8 and unreadable or non-UTF-8 files fail discovery, unlike Git's byte-oriented behavior and the tolerant handling of repository/global excludes.
- CLI filesystem discovery tests depend on host global excludes (crates/mempalace-cli/src/main.rs): Some CLI tests do not isolate the user's global Git excludes configuration, so local rules can alter expected discovery counts and make tests environment-dependent.

## Missing Tests

- Remote-only and write:both canonical re-mining after a stored path becomes secret-shaped or otherwise ineligible.
- Remote reconciliation behavior for discovered files that produce zero chunks.
- A targeted Git subdirectory or empty-but-complete discovery test clarifying the interaction between directory-scoped discovery and identity-scoped cleanup.
- Non-UTF-8 nested ignore-file handling.
- CLI filesystem-walk tests with isolated global Git excludes.

## Disputed Issues

- Whether an empty eligible source set should trigger canonical cleanup: some reviewers consider it authoritative retroactive cleanup, while others identify a reachable Git-subdirectory case where directory-scoped emptiness can affect repository-identity-scoped rows.

## Outstanding Concerns

- The stable cleanup prefix is repository-identity-scoped while discovery may be subdirectory-scoped, so an empty or all-ineligible subdirectory result could have a broader deletion blast radius than the checkout being mined.
- The all-or-nothing completeness flag suppresses the entire cleanup sweep when any tracked path is missing locally, conservatively preserving stale rows but also delaying legitimate deletions.

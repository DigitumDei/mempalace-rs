## Executive Summary

The branch adds diary summaries, detail lookup by entry ID, and reconciliation cleanup. Reviewers agree that concurrent diary ingestion can delete the winning writer’s summary because summary ownership is not tracked, making the branch unsafe for PR. They also identified an empty-input panic and a cross-store deletion failure mode; orphan-pruning semantics remain unresolved.

## Blocking Issues

- Diary summary ownership race (src/engine.rs): Concurrent ingests for the same drawer ID can overwrite a shared summary row, then the losing writer can delete the successful writer’s summary after a duplicate LanceDB error. Cleanup must be ownership-aware.

## Non-Blocking Issues

- Empty diary ingest request panics (src/engine.rs): commit_diary_ingest indexes request.drawers[0] without validating that the request contains a drawer, causing malformed input to panic instead of returning an error.
- Cross-store deletion is not failure-safe (src/lib.rs): tool_delete_drawer deletes the LanceDB drawer before SQLite summary cleanup. If SQLite deletion fails, the drawer is irreversibly gone, the summary is orphaned, and change logging is skipped.

## Missing Tests

- Concurrent diary ingests for the same drawer ID with different summaries, verifying the successful writer retains its summary.
- An empty drawers request to commit_diary_ingest.
- SQLite summary-cleanup failure after successful LanceDB drawer deletion.
- The intended behavior for an uncommitted LanceDB drawer with no manifest and no stale-run reference.

## Disputed Issues

- Whether narrowing prune_orphaned_rows to stale-run IDs is a confirmed recovery regression or an intentional, undocumented contract change.
- Whether the empty-input panic and cross-store deletion failure should be classified as blocking rather than non-blocking.

## Outstanding Concerns

- The changed orphan-pruning behavior removes cleanup coverage for unmanifested LanceDB rows; its intended contract should be documented and tested.
- The duplicate committed-drawer query during reconciliation may produce inconsistent snapshots around concurrent commits and adds unnecessary work.
- Several smaller review concerns remain, including unreachable entry_id filtering and acceptance of empty summaries.
